# Контекст проекта — где что лежит

Чтобы решения и нюансы владельца не терялись между сессиями и со временем:

| Файл | Что внутри | Когда читать |
|---|---|---|
| `.claude/rules/00-project.md` | правила разработки: стек, ООП, БД, безопасность, проверки | всегда (подгружается сам) |
| `.claude/rules/10-owner.md` | приоритеты владельца, как он ставит задачи, выпуск, данные, индекс, как вести контекст | всегда (подгружается сам) |
| `.claude/rules/20-kp-ui.md` | документ КП, шаблоны, интерфейс (ПК, телефон, тёмная тема) | правка `app/web/**`, шаблонов |
| `.claude/rules/30-catalog.md` | каталог, оборудование, фото, фиды поставщиков, база | каталог, фиды, ИИ, хранилище |
| `.claude/rules/40-admin.md` | клиенты, контрагенты, менеджеры, доступ, «Настройки» | клиенты, админка, вход |
| `.claude/rules/50-deal.md` | экономика сделки, НДС, таможня, график платежей, логистика | экономика, логистика |
| `.claude/rules/60-stations.md` | станции в контейнере: компоновка, двери, вентиляция, маркизы, чертёж, 3D, ТЗ, расчёты | станции, ТЗ, правила |
| `docs/context/app-map.md` | карта приложения: модули, классы, данные, механизмы, этапы по версиям | новая сессия, незнакомая часть |
| `docs/context/owner-general.md` | общие пункты владельца по датам (порядок работы, выпуск, проверки) | спор о порядке работы |
| `docs/vent-calc.md` | вентиляция станции: формулы, исходные, предупреждения, пример «винтовой 75 кВт» | задача по вентиляции / отоплению станции |

Файлы `20…60` подгружаются автоматически, когда работа идёт с файлами раздела (поле `paths`); перед задачей по разделу их
стоит прочитать целиком. Что и когда реализовано — `APP_VERSIONS` в `app/web/js/features/help.js`, README, `git log`.

Пополнять: каждое новое требование или правку владельца — пунктом «- (ДД.ММ) …» в файл раздела в том же коммите, что и
код; изменившееся — исправлять с пометкой «(уточнено ДД.ММ)» или «(отменено ДД.ММ)». Ключи, пароли, данные клиентов и
закупочные условия поставщиков сюда не писать: репозиторий публичный.
