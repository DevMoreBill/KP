# Выпуск версии

Аргумент: $ARGUMENTS — номер новой версии. Нет номера — взять текущий из `app/version.py` и увеличить: исправления — третье
число, новые возможности — второе.

1. **Версия**: `python3 .claude/skills/vypusk/vypusk.py <версия>` — ставит номер в `app/version.py` и `APP_VERSION` (help.js)
   и печатает, каких записей о версии не хватает.
2. **Записи о версии** (по сути изменений, коротко, по-русски):
   - `app/web/js/features/help.js` → `APP_VERSIONS` — первой записью `['<версия>', 'ДД.ММ.ГГГГ', [...]]`: пункты для
     менеджера («что изменилось для вас»), без названий классов;
   - `README.md` — раздел «**<версия> — …:**» со списком перед прежней версией (для разработчика: классы, данные, проверки);
   - `docs/context/app-map.md` — строка «- **<версия>** (ДД.ММ) — …» в этапах по версиям;
   - `Инструкция.txt` — только при заметных для менеджера изменениях;
   - решения и поправки владельца — пунктами «- (ДД.ММ) …» в файлах `.claude/rules/NN-*.md` своего раздела.
   Повторно `python3 .claude/skills/vypusk/vypusk.py --check` — должно быть «все записи на месте».
3. **Проверки** — по затронутому (полный набор делает CI при отправке): `python3 tests/run_all.py --changed` — всё OK;
   при изменениях интерфейса — `python3 tests/ui/progon.py --changed --out <папка>` (этапы и режимы — по правкам с прошлой
   сборки) и посмотреть снимки затронутых окон. Полный `--strict` и все режимы прогона — только при большой переделке.
4. **Репозиторий**: `git add -A` → `python3 .github/scripts/repo_guard.py .` (нет баз, выгрузок, ключей).
5. **Коммит**: заголовок `<версия>: что сделано` + список изменений (как в `git log`), в конце строки соавторства из
   системных указаний сеанса. Без названий моделей.
6. **Отправка**: `git push -u origin <рабочая ветка>`; дождаться CI (при отправке — только проверки, EXE не собирается).
7. **Сборка EXE** — НЕ запускать без команды владельца. По команде — сразу (локально ничего не перезапускать; коммит, уже
   проверенный CI при отправке, собирается без повторных проверок) workflow `build-exe.yml` вручную с `release=true`, затем
   проверить выпуск: EXE, ZIP и пакет обновления `KP-Obnovlenie-<версия>.zip`.
8. **Отчёт** владельцу — по-русски, коротко: что сделано, что проверено, что не сделано и почему.
