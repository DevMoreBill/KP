# Прогон интерфейса

Команда (из корня репозитория):

```
python3 tests/ui/progon.py --modes pc,pcd,ph,phd,tab --out <папка во временной/рабочей папке сеанса>
```
Режимы: pc — ПК 1440×900, pcd — ПК 1366×768 тёмная, ph/phd — iPhone 16 Pro Max светлая/тёмная, tab — планшет iPad Air 820×1180 (касания).

- `--stages client,cat,editor,station,price,deal,steps,preview,save,files,mail,journal,misc,settings,bitrix,dbl` — только эти этапы
  (для проверки одного окна). Этапы зависят от предыдущих: «save» требует заполненного КП (client, cat, price, steps).
- Данные — вымышленные (`tests/kit.py`, SampleData), рабочая база не используется. `--db <копия.sqlite3>` — КОПИЯ базы
  владельца для прогона на настоящем каталоге (копию не класть в репозиторий).
- Режимы идут параллельно, полный прогон ПК + телефон — 6–8 минут; четыре режима — около 30–40 минут.
- Зависания (3.213.1): 3D-вид станции (WebGL на процессоре) режимы строят по очереди (`GlQueue`, папка-замок `gl.lock`);
  этап дольше `--stage-max` минут (по умолчанию 10) — `HUNG` в отчёте, режим перезапускается со следующего этапа
  (`StageGuard`, профиль браузера `<out>/profile/<режим>` — то же КП и вкладки), не больше 3 раз; браузер зависшего режима
  закрывается. `HUNG` — сбой в итоге: смотреть, программа ли не отвечает (бесконечный расчёт) или стенд перегружен.
- Не останавливать прогон `pkill -f progon` из оболочки, где в команде есть это слово: команда убьёт и саму оболочку;
  останавливать по номеру процесса (`ps -eo pid,args | grep "[p]rogon.py --modes"`, затем `kill <pid>`).

Разбор:
1. `<out>/report.txt` — сводка по режимам; код выхода 1 — сбой сценария (SCRIPT), ошибка JavaScript (pageerror), двойное
   окно (DOUBLE), пустое окно (EMPTY), зависший этап (HUNG).
2. SCRIPT — сначала понять, сценарий это или программа: открыть `shots/<режим>/ERR_<этап>.png` и снимок перед ним. Сценарий —
   поправить `tests/ui/progon.py`; программа — исправить и проверить этот этап снова (`--stages`).
3. Замечания проверок (`btnTxt`, `overlap`, `contrast`, `small`, `font`) — смотреть снимки затронутых окон: декоративное,
   намеренное и уже известное — не ошибки; настоящее (обрезанный текст, наложение кнопок, мелкая цель нажатия на телефоне)
   — исправить.
4. Отчёт владельцу — что нашлось, что исправлено, снимки затронутых окон (ПК, телефон, тёмная тема) — по его просьбе.
