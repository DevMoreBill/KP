# Проект «Конструктор КП ПНЕВМОТЕХ» — правила разработки

## Стек и ограничения
- Сервер: Python 3, **только стандартная библиотека** (`app/*.py`, `http.server`, SQLite через `sqlite3`). Не добавлять
  зависимости из PyPI/npm без явной просьбы — программа собирается в один EXE (PyInstaller, `kp.spec`,
  `.github/workflows/build-exe.yml`). Новый модуль сервера — добавить в `hiddenimports` в `kp.spec`.
- Клиент: обычный JavaScript без сборщика и фреймворков (`app/web/js/**`, глобальные функции, `'use strict'`),
  CSS — `app/web/css/*.css`, подключение — `app/web/index.html`.
- Интерфейс, сообщения, комментарии, журнал изменений, коммиты — **на русском**.

## ООП — главное правило (решение владельца проекта)
- Новый код — только в классах. Сервер: классы с состоянием (`FeatureAccess(store)`, `DealTrack(store)`, `Mailer(store)`)
  или со статическими методами (`OfferTerm.until`, `Val.day`); маршруты — методы контроллеров `web_api.py` (`@route`).
  Клиент: классы со статическими или обычными методами (`Drafts`, `Presets`, `NewKp`, `KpLoader`, `KpDate`, `StepList`,
  `ClientCard`, `MyDay`), окна — через `Modal`. Новых глобальных функций и процедурных модулей не заводить.
- Один класс — одна ответственность; данные и действия над ними — вместе; служебное — «_метод»; константы — атрибуты класса.
- Изменяя старый процедурный код, переносить затронутую часть в класс по месту (без переписывания всего файла разом).

## Стиль: как в окружающем коде
- Не переписывать существующий код под чужие правила «неизменяемые данные», «аннотации типов везде», «файлы ≤ 400 строк»:
  состояние КП (`S`, `S.deal`) намеренно изменяемое, аннотаций типов в проекте нет. В новом коде — по месту, как рядом.
- Формат коммитов — как в истории репозитория (`3.x.y: что сделано` + список), а не `feat:/fix:`.

## База данных
- Схема меняется только миграциями в `app/storage.py` (атомарно, `MIGRATION_FILL`), без ручной правки рабочей базы
  пользователя. Совместная правка — номер ревизии (`rev`, заголовок `X-KP-Rev`, ответ 409).

## Безопасность
- SQL — только с параметрами (`?`), поиск по `LIKE` — через `like_arg`; имена таблиц и полей не собирать из ввода.
- Ввод проверять на сервере, на границе (как `UserPrefs.save`, `Val`): известные поля, длина, формат; ошибка — `ValueError`
  с понятным текстом для пользователя, без путей, SQL и трассировки.
- В HTML всё пользовательское и из базы — через `esc(...)`; `innerHTML` с сырыми данными не собирать.
- Админка: изменения — только с сессией администратора и токеном `X-CSRF-Token` (`admin.is_admin`); новые маршруты
  изменения данных — так же. Пути к файлам из запроса — не выходить за свою папку.
- Ключи API, пароли и токены — не в репозиторий и не в журналы; базы и выгрузки пользователя (`*.sqlite3`, `kp*.zip`) — тоже.

## Проверки перед коммитом
- `python3 tests/run_all.py` — pyflakes, ESLint для `app/web/js` (`eslint.config.mjs`, необъявленные имена), наборы `tests/` на стенде
  со сгенерированной базой; то же CI делает при каждой отправке, и EXE собирается только после этого. Новая функция сервера — проверка
  в `tests/` (на `kit.Stand`/`SampleData`, без данных пользователя). Сценарии Playwright — на копии базы (не на рабочей).
- Версия: `app/version.py` + `APP_VERSION` и журнал в `app/web/js/features/help.js`, README.
