# Владелец проекта: как работать, что важно, где лежит контекст

Программа — «Конструктор КП ПНЕВМОТЕХ» (группа компаний ПНЕВМОТЕХ: компрессоры, мотопомпы, насосы, генераторы, сервис,
запчасти). Пользователи — менеджеры отдела продаж: КП, экономика сделки, логистика, станции в контейнере. Сервер отдела —
Windows 10 (один EXE, папка программы C:\KP), менеджеры работают из браузера на ПК и телефоне (ориентир — iPhone 16 Pro Max).
Владелец ставит задачи сам, по-русски, часто голосом (возможны опечатки и автозамены — понимать по смыслу и записывать,
как понял).

## Приоритеты (решение владельца)
1. Логика вычислений и достоверность данных: расчёты, нормы, характеристики — по источникам, без выдуманных значений;
   неподтверждённое помечать «требует подтверждения» (правила станций — `app/web/rules/stations.json`).
2. Простота, удобство и очевидность для менеджера, которому некогда разбираться: «чем компактнее и понятнее, тем лучше»
   во всём приложении; подробности — под раскрытием и в «?»; новых форм без нужды не добавлять — в имеющихся окнах.
3. В документах для заказчика — без лишних вопросов и пометок; мелкие погрешности данных — в пользу заказчика.

## Как владелец ставит задачи и чего ждёт
- «Подумай / предложи, ничего не интегрируй» — только предложение, код — после его «давай / делай». «Просто ответь» — ответ
  текстом, ничего не внедрять.
- Часто: ассистент даёт нумерованный список, владелец отвечает номерами («всё кроме 6 и 7»). Номера сами по себе теряются —
  выбранное записывать словами (в файл раздела ниже).
- Большие задачи — автономно («меня не спрашивай»): все вопросы задать сразу до начала, дальше работать без него,
  скрупулёзно, до рабочего и проверенного результата с первого раза (не частичный отчёт; повторные просьбы одного и того же
  — признак, что прошлый раз не доделано). Проверять на синтетических данных и на копии его базы, не на рабочей.
- После работы — предлагать, что ещё улучшить для скорости и удобства менеджера; если что-то логичнее перенести между
  разделами — предложить. Готовность приложить скриншоты затронутых окон (ПК, телефон, тёмная тема).
- Отчёт — по-русски, коротко и по сути: что сделано, что проверено, что не сделано и почему. Инструкции по установке —
  пошагово «для новичка», только с кнопками, которые есть в выпущенной у него версии.
- Регулярно сам предлагать и делать: аудит (мусорный и неиспользуемый код, ошибки, уязвимости, скорость), полный прогон
  интерфейса (ПК и телефон, светлая и тёмная тема, сползания окон и полей).

## Выпуск (каждое изменение)
- Версия: `app/version.py`, `APP_VERSION` и запись в `APP_VERSIONS` (`app/web/js/features/help.js`), раздел в README,
  при заметных для пользователя изменениях — `Инструкция.txt`.
- `python3 tests/run_all.py --strict` (всё OK, ESLint без предупреждений) → `git add -A` → `python3 .github/scripts/repo_guard.py .`
  → коммит `3.x.y: что сделано` + список → push в рабочую ветку → CI зелёный (при отправке — только проверки, EXE не собирается).
- (17.10) «На будущее и впредь компиляция приложения только по моей команде»: сборку EXE и выпуск (workflow `build-exe.yml`,
  запуск вручную, `release=true`) — ТОЛЬКО когда владелец скажет «собери / выпусти / компилируй»; после команды — проверить,
  что выпуск опубликован (EXE, ZIP, пакет обновления `KP-Obnovlenie-*.zip`). Владелец спрашивает «сборка прошла?» — отвечать фактом.
- (18.10, 3.103.0) Пакет обновления подписывается при выпуске секретом репозитория `KP_UPDATE_KEY` (закрытый ключ Ed25519; открытый —
  `app/update_sign.py`). Без секрета выпуск не делается (шаг «Файлы релиза» падает с подсказкой). Закрытый ключ — никогда в репозиторий,
  журналы и чат; новый ключ = новый открытый ключ в коде и выпуск полным комплектом.
- Обновление ставится пакетом из «Настроек» без переустановки; обновление не должно ломать запуск и базу (откат при сбое).
  Сборка для Windows 7 не нужна. Программу не утяжелять: фото, база и копии — на сервере отдела, не в EXE и не в репозитории.

## Данные и безопасность
- Репозиторий публичный: ключи API, пароли, токены, базы и выгрузки пользователя (`*.sqlite3`, `kp*.zip`), данные клиентов,
  скидки и закупочные условия поставщиков — никогда в репозиторий, журналы и выпуски.
- Базу пользователя не заменять — только миграции (`app/storage.py`); правка данных каталога — без поломки цен, остатков и
  фидов. Удаление — только в админке («Настройки») с паролем; у менеджеров кнопок удаления нет.
- Внешние API — доступные из РФ; нормы и характеристики — перепроверять по интернет-источникам, а не по памяти.

## Где контекст (читать перед задачей по разделу)
- `.claude/rules/00-project.md` — правила разработки: стек, ООП (главное правило владельца), БД, безопасность, проверки.
- Требования владельца по разделам — по датам, с уточнениями (подгружаются при работе с файлами раздела; перед задачей —
  прочитать нужный целиком): `20-kp-ui.md` (документ КП, шаблоны, интерфейс), `30-catalog.md` (каталог, фото, фиды, база),
  `40-admin.md` (клиенты, контрагенты, менеджеры, доступ, админка), `50-deal.md` (экономика сделки, логистика),
  `60-stations.md` (станции в контейнере: компоновка, двери, вентиляция, маркизы, чертёж, 3D, ТЗ, расчёты),
  `70-crm.md` (кабинет менеджера: сделки, дела, график, отдел).
- `docs/context/app-map.md` — карта приложения (модули, классы, данные, механизмы, этапы по версиям);
  `docs/context/owner-general.md` — общие пункты владельца по датам.
- Что и когда сделано: `APP_VERSIONS` в `help.js`, README (разделы по версиям), `git log` («3.x.y: …»).

## Как сохранять контекст дальше
- Каждое новое требование, правку или решение владельца — сразу пунктом «- (ДД.ММ) суть со всеми числами и нюансами» в
  файл раздела, в том же коммите, что и код. Меняет прежнее — старый пункт исправить с пометкой «(уточнено ДД.ММ)» или
  «(отменено ДД.ММ: …)», а не держать два противоречащих.
- Поправка владельца «сделал не так» — записать, как правильно, отдельным пунктом: это самые ценные нюансы.
- Новый раздел программы — новый файл `.claude/rules/NN-раздел.md` с `paths:` своих файлов и строка в индексе выше.

  8) прогон на копии базы — нужны владелец (ключи, копия базы); 6) deal.js — в классы; 7) общая задержка ввода `Debounce`;
  9) повторная проверка помощниками безопасности и расчётов — напоминание через 2 недели.
