Ты — инженер данных. Подготовь позиции каталога оборудования для программы «Конструктор КП ПНЕВМОТЕХ» в её формате импорта. Результат загружается кнопкой «Каталог → Загрузить» без правок и добавляется в действующую базу (сейчас в ней 744 позиции: ДГУ Tide Power, HERTZ, Energo, ТСС, AGG; винтовые компрессоры SEIZEAIR; осветительные мачты; чиллеры Thermex Energy).

ВО ВЛОЖЕНИИ
1. Документы производителя: PDF, DOCX, XLSX — каталоги, паспорта, datasheet, прайсы.
2. Картинки — одним из двух способов, бывает и так и так одновременно:
   а) встроены в документы — извлеки их;
   б) лежат в отдельных папках. Имя файла картинки соответствует названию модели.
      Пример: «FB400-LP.jpg», «S-PMV-08A.png», «TMR 22-660 (фото).jpg».
3. catalog_example.json — три реальные позиции из базы: ДГУ, винтовой компрессор, чиллер. Структуру, стиль текстов, названия групп и формат значений повторяй по ним.
4. equipment_types.json (встроенные типы) и user_types.json (свои типы, например «Чиллеры») — ключи attrs, названия групп и слоты галереи бери отсюда.

ЧТО СДАТЬ
1. catalog_<производитель>.json — по файлу на производителя, UTF-8, каждый не больше 40 МБ; если больше — раздели на части _1, _2 …:
   { "format": "kp-catalog", "version": 1, "items": [ …позиции… ] }
2. report.txt — отчёт (см. в конце).
Картинки кладутся прямо в позиции как data URL: "src": "data:image/jpeg;base64,…" или "data:image/png;base64,…". Программа при загрузке сохранит их у себя; одинаковые по содержимому файлы она хранит один раз.

ПОЗИЦИЯ КАТАЛОГА (одна модель = одна позиция)
{
 "id": "seizeair_s-pmv-08a",        // <производитель>_<модель>: латиница и цифры в нижнем регистре, «-» и «_»; без пробелов и других знаков; не длиннее 64; уникален
 "name": "Винтовой компрессор SEIZEAIR S-PMV-08A с частотным преобразователем",   // вид (ед. ч.) + производитель + модель + отличительная особенность / исполнение
 "spec": "7,5 кВт · 1,08 м³/мин при 7 бар · до 8 бар · ПМ-двигатель IE4, IP23 · 750 × 560 × 860 мм",   // 3–5 главных фактов через « · »
 "price": 0,                        // цена продажи за шт. в копейках: 1 500 000,00 руб. = 150000000; нет цены — 0
 "pageTitle": "Винтовой компрессор SEIZEAIR S-PMV-08A",   // заголовок страницы в КП: вид + производитель + модель
 "photoCaption": "Общий вид серии S-PMV",   // подпись к главному фото; нет — ""
 "about": "…",                      // необязательно: 1–3 предложения о производителе/серии; нечего сказать — поле не добавляй
 "features": [ {"id": "9a6b612a", "label": "О серии", "text": "…"}, … ],
 "groups": [ {"name": "Основные", "rows": [ {"k": "Модель", "v": "S-PMV-08A", "hl": false}, … ]}, … ],
 "hint": { "title": "Винтовые компрессоры", "model": "SEIZEAIR S-PMV-08A", "desc": "…",
           "kpis": [ {"num": "1,08", "unit": "м³/мин", "cap": "производительность при 7 бар"}, … ] },
 "attrs": { "cat": "comp_screw", "maker": "SEIZEAIR", "series": "S-PMV", "model": "S-PMV-08A", … },
 "photo": {"src": "data:image/jpeg;base64,…", "w": 492, "h": 603},   // главное фото; нет — null
 "photoIsSimilar": true,            // только если на фото другая модель серии или общий вид серии
 "photoSource": "общий вид серии S-PMV (модель на фото не указана)",   // только вместе с photoIsSimilar
 "logo": {"src": "data:image/png;base64,…", "w": 480, "h": 123},   // логотип производителя; нет — null
 "gallery": [],                     // дополнительные изображения, см. ниже
 "prices": []
}
Поля cost, costCur, margin, mmode, priceCur, updatedAt не добавляй: закупку и маржу менеджеры ведут сами.

ПРАВИЛА ПО ПОЛЯМ
• features: 2–7 блоков. Короткие блоки до ~220 знаков («Двигатель», «Альтернатор», «Панель управления», «Исполнение», «Преимущества», «Компрессорный узел», «Теплообменники») выводятся рядом с фото. Длинные (о серии, стандартная комплектация) — отдельными блоками. id — 8 случайных hex-символов, уникальных внутри позиции. Без рекламных штампов.
• groups — названия групп как в базе:
  ДГУ (dgu): «Основные», «Двигатель», «Расход топлива», «Альтернатор», «Габариты и масса (открытое исполнение)» / «Габариты и масса (в кожухе)» / «Габариты и масса (контейнер 20 футов)» / «Габариты и масса (контейнер 40 футов)», «Комплектация».
  Винтовой компрессор (comp_screw): «Основные», «Компрессор», «Двигатель», «Система воздушного охлаждения», «Водяное охлаждение (исполнение W)», «Управление и защита», «Габариты и масса», «Опции», «Примечания».
  Осветительная мачта (light): «Основные», «Освещение», «Двигатель», «Генератор», «Топливо», «Габариты и масса».
  Чиллер (chiller): «Основные», «Температурные параметры», «Испаритель», «Конденсатор», «Фрикулинг», «Электрические характеристики», «Шумовые характеристики», «Габариты и вес», «Комплектация».
  Первая группа — «Основные», первая её строка — «Модель». Пустые группы не добавляй.
  hl: true — только у 3–6 ключевых параметров: мощность, производительность, давление, холодопроизводительность, расход. Они выводятся крупными плитками рядом с фото, поэтому значение до 28 знаков.
  Перечни (защиты, комплектация, условия измерений) допустимы длинным текстом в одной строке «v».
• Числа и единицы по-русски: десятичная запятая («2,54 л»), пробел перед единицей, «×» в габаритах («3700 × 1400 × 1880 мм»), диапазоны через « – » («21,00 – 70,00 м³/мин»), «м³/мин», «кВт», «кВА», «дБ(А)», «°C», «бар», «А».
• hint: title — вид оборудования во мн. ч. (как coverTitle типа); model — производитель + модель; desc — одно-два предложения; kpis — ровно 4 параметра (num — строка с запятой, unit, cap — короткая подпись).
• attrs — фильтры каталога; ключи только из "fields" своего типа, с теми же именами:
  dgu:        type «ДГУ», maker, model, series, engine, engineModel, alternator, controller, kw, kwMax, kva, execution, voltage, phases, cat
  light:      те же ключи, что у dgu; type «Осветительная мачта»; execution «На шасси»
  comp_screw: maker, model, series, flow, pressure, kw, drive, vsd, execution, cooling, dryer, voltage, noise, size, mass, cat
  chiller:    maker, model, series, coolingCapacity, type, execution, compressorType, compressorCount, refrigerant, evaporatorType, condenserType, coolant, coolantTempIn, coolantTempOut, ambientTemp, powerConsumption, voltage, phases, maxCurrent, eerBrutto, eerNetto, soundPressure1m, soundPressure5m, soundPressure10m, length, width, height, weight, cat
  Поле с "num": true — число (точка как разделитель: 1.08); нет данных — null. Поле с "values" — значение только из этого списка. Пример: execution «Открытое» / «В кожухе» / «Блок-контейнер»; phases «3 фазы» / «1 фаза».
  Новый вид оборудования, которого нет в типах, — "cat": "other" и отметка в отчёте; своих ключей не придумывай.
• gallery: [{"id": "4e7158f5", "src": "data:…", "w": 195, "h": 140, "caption": "Панель управления", "slot": "Контроллер", "at": "feat:62c5bf48", "on": true}]
  slot — из "gallerySlots" типа или "".
  Фото узла (двигатель, винтовой блок, контроллер, испаритель) привяжи к его блоку описания: "at": "feat:<id блока features>"; остальные — "at": "free".
  Чертежи и схемы: caption «Габаритный чертёж» / «Электрическая схема».
• Та же модель уже есть в базе (совпадает производитель и модель): бери тот же id, что в базе, если он известен из образцов; иначе — отметь в отчёте. Программа обновит позицию и сохранит её цену и историю цен.

ЛОГОТИПЫ — ОДИН ПРОИЗВОДИТЕЛЬ = ОДИН ЛОГОТИП
• У всех позиций одного производителя "logo" — байт-в-байт одна и та же картинка: одинаковые data URL, "w" и "h". Только так программа сохранит её одним файлом.
• Разные варианты логотипа из разных документов (размер, фон, сжатие, обрезка) — это один логотип. Сравнивай визуально и выбери лучший:
  – официальный, полный, горизонтальный;
  – наибольшего разрешения, без артефактов сжатия;
  – PNG с прозрачным фоном лучше, чем на белом.
  Остальные варианты не используй.
• Логотипы серий и суббрендов, сертификатов, выставок, дилеров, иконки, водяные знаки в "logo" и "gallery" не попадают.
• Длинная сторона логотипа — 360–700 px.

КАРТИНКИ
1. Встроенные в документ: извлекай исходный объект изображения, а не снимок страницы. Если картинка доступна только как часть страницы (скан) — отрисуй страницу не ниже 300 dpi и вырезай из неё. Модель определяй по ближайшему заголовку, таблице или подписи. Оформление страниц, фоны, иконки, колонтитулы не бери.
2. Из папок: сопоставляй имя файла с моделью без учёта регистра, пробелов, дефисов, подчёркиваний, точек, слэшей и слов «кожух», «открытый», «фото», «img».
   Пример: «FB400-LP.jpg» = «FB400LP» = «fb400 lp».
   • Несколько файлов на модель: без уточнения или «общий вид» — в "photo", остальные — в "gallery" с caption из уточнения в скобках или после «_».
   • Картинка на серию (имя = серия): ставь главным фото моделям серии без своего фото, с "photoIsSimilar": true и "photoSource": «общий вид серии …».
   • Нет совпадения — в отчёт, не угадывай.
3. Вырезание — максимально аккуратно:
   • граница — по фактическому контуру объекта; объект целиком, без срезанных краёв корпуса, колёс, патрубков, кабелей, рукояток, надписей на изделии;
   • ровное поле вокруг — 3–5 % от длинной стороны, одинаковое со всех сторон; объект не касается края кадра;
   • в кадр не попадают соседние картинки, текст, подписи, номера страниц, куски таблиц, рамки и тени вёрстки; без этого нельзя — возьми другой источник и отметь в отчёте;
   • пропорции не меняй: без растяжения, поворота, перспективы; исключение — выпрями явный наклон скана;
   • фон не заменяй и не дорисовывай, ретушь запрещена; прозрачность PNG сохраняй;
   • чертежи режь по внешней рамке вместе с размерными линиями и подписями;
   • картинку с уже аккуратными полями не режь;
   • после обрезки просмотри каждую; сомнительные — в отчёт с пометкой «проверить».
4. Формат: JPG качества 88–90 для фото; PNG для прозрачности, схем, логотипов. Длинная сторона — не больше 1600 px, без апскейла, уменьшение с Lanczos. "w" и "h" — фактический размер итоговой картинки.

КАЧЕСТВО
• Ничего не выдумывай: только данные из документов. Нет параметра — нет строки. Противоречие между документами — бери более новый документ и отметь в отчёте.
• Одна модель — одна позиция. Исполнения (открытое / в кожухе, A / W, 50 / 60 Гц) — отдельные позиции со своими id, если отличаются характеристики или габариты.
• Перед сдачей проверь:
  – файл валиден, "format": "kp-catalog", у каждой позиции есть id и name;
  – id уникальны по всем файлам;
  – у всех позиций одного производителя одинаковый "logo";
  – id блоков features уникальны внутри позиции, все "at": "feat:…" ссылаются на существующие блоки;
  – attrs.cat из списка типов, числовые attrs — числа или null;
  – каждый "src" — корректный data URL JPG/PNG, "w"/"h" совпадают с размером картинки.

report.txt
• сколько позиций собрано — по производителям и типам;
• логотип каждого производителя: откуда взят, размер;
• позиции без фото, с фото похожей модели (photoIsSimilar), без логотипа, с неполными характеристиками;
• картинки, не привязанные к модели (имя файла + предполагаемая модель);
• вырезанные картинки с пометкой «проверить» и причиной;
• противоречия в данных и выбранное значение;
• позиции с неуверенным типом (attrs.cat) и модели, которые, возможно, уже есть в базе.
