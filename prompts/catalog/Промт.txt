ТЕХНИЧЕСКОЕ ОПИСАНИЕ — МАКСИМАЛЬНО ПОДРОБНО, НО ТОЛЬКО ИЗ ДОКУМЕНТОВ
• features — 3–7 блоков по существу, без рекламы: «О серии», затем узлы категории (у ДГУ — «Двигатель», «Альтернатор», «Панель управления», «Исполнение»; у компрессора — «Компрессорный блок», «Двигатель», «Привод», «Система охлаждения», «Управление»; у осушителя — «Принцип работы», «Теплообменник», «Управление», «Отвод конденсата»; у ресивера — «Изготовление», «Контроль качества», «Комплектация»; у запчасти — «Назначение», «Применимость», «Замена»), в конце — «Стандартная комплектация».
  Короткий блок (до ~220 знаков) выводится в КП рядом с фото узла; длинный — отдельным абзацем. id — 8 случайных hex-символов, уникальны внутри позиции.
• groups — ВСЕ параметры, которые есть в документах, сгруппированные по группам категории (см. «КАТЕГОРИИ»). Первая группа «Основные», первая строка — «Модель». Затем — группы узлов, «Электрика» / «Электрические характеристики», «Условия эксплуатации», «Габариты и масса», «Комплектация», «Опции», «Примечания» (условия измерений, стандарты). Пустые группы не добавляй.
  Каждая строка — один параметр: "k" — название с уточнением условий («Производительность при 7 бар»), "v" — значение с единицей. Перечни (защиты, комплектация) — одной строкой через «; ».
  hl: true — у 3–6 главных параметров категории (мощность, производительность, давление, точка росы, объём, ток); значение до 28 знаков — они выводятся крупными плитками.
• Числа и единицы по-русски: десятичная запятая («2,54 л»), пробел перед единицей, «×» в габаритах («3700 × 1400 × 1880 мм»), диапазоны через « – » («21,00 – 70,00 м³/мин»), «м³/мин», «л/мин», «кВт», «кВА», «бар», «°C», «дБ(А)», «А», «В», «Гц», «л», «кг».
• hint — титул КП: title — категория во мн. ч. (coverTitle категории); model — производитель + модель; desc — 1–2 предложения о модели; kpis — ровно 4 ключевых параметра (num — строка с запятой, unit, cap — короткая подпись).
• attrs — параметры для фильтров каталога: cat, maker, series, model + ключи "fields" категории с теми же именами. Поле с "num" — число с точкой (1.08) или null; поле с "values" — значение только из списка. Не заполняй то, чего нет в документах.
• Ничего не выдумывай. Нет параметра — нет строки. Противоречие между документами — бери более новый документ и отметь в отчёте.
• Исполнения (открытое / в кожухе / контейнер, A / W, 50 / 60 Гц, 8 / 10 / 13 бар), если отличаются характеристики или габариты, — отдельные позиции со своими id.

Не впихивай оборудование в чужую категорию и не используй «other», если таких моделей больше одной. Опиши новую категорию в "types" того же файла, и позиции укажут её id в attrs.cat:
{ "id": "nitrogen_gen",               // латиница, цифры, «_», с буквы, 2–31 знак; не совпадает с существующими
  "group": "Подготовка воздуха",       // раздел: один из существующих («Генераторы», «Компрессоры», «Подготовка воздуха», «Вспомогательное оборудование», «Насосы», «Запасные части», «Холодоснабжение», «Прочее») или новый
  "name": "Генераторы азота",          // мн. ч. — название категории в каталоге

ЗАПАСНЫЕ ЧАСТИ И ЗИП (cat "spare")
name: вид + назначение + производитель запчасти + артикул («Фильтр масляный Dalgakiran 2205…» ). attrs: part — вид из списка; forType — для какого оборудования; forMaker — производитель техники; engine — двигатель/узел; forModels — модели, к которым подходит, через запятую; article — артикул; original — «Оригинал» или «Аналог»; service — интервал замены в моточасах. Комплекты ТО и ЗИП — отдельными позициями (part «Комплект ТО» / «Комплект ЗИП») с составом в groups → «Комплектация».

ЛОГОТИПЫ — ОДИН ПРОИЗВОДИТЕЛЬ = ОДИН ЛОГОТИП
• У всех позиций одного производителя "logo" — одна и та же картинка байт в байт (одинаковые src, w, h).
• Из вариантов выбери лучший: официальный, полный, горизонтальный, максимального разрешения, PNG с прозрачным фоном; длинная сторона 360–700 px.
• Логотипы серий, сертификатов, выставок, дилеров, иконки и водяные знаки не используй.

КАРТИНКИ
1. Из документов извлекай исходный объект изображения, не снимок страницы. Если картинка есть только на скане — отрисуй страницу не ниже 300 dpi и вырежи. Модель определяй по ближайшему заголовку, таблице или подписи.
2. Из папок сопоставляй имя файла с моделью без учёта регистра, пробелов, «-», «_», «.», «/» и слов «фото», «img», «кожух», «открытый». Несколько файлов на модель: общий вид — "photo", остальные — "gallery" с caption из уточнения в имени. Картинка на серию — главное фото моделям серии без своего фото, с "photoIsSimilar": true и "photoSource". Нет совпадения — в отчёт, не угадывай.
3. Фото другой категории или другого производителя позиции не ставь никогда.
4. Вырезание — максимально аккуратно: по фактическому контуру объекта, объект целиком (без срезанных колёс, патрубков, кабелей, надписей на изделии); ровное поле 3–5 % длинной стороны; без соседних картинок, текста, подписей, рамок и теней вёрстки; без поворота, растяжения, ретуши и дорисовки фона; прозрачность PNG сохраняй; чертежи режь по внешней рамке вместе с размерами; аккуратную картинку не режь.
5. gallery: [{"id": "4e7158f5", "src": "data:…", "w": 800, "h": 560, "caption": "Панель управления", "slot": "Контроллер", "at": "feat:<id блока>", "on": true}] — фото узла привязывай к его блоку описания ("at": "feat:<id из features>"), остальное — "at": "free". slot — из слотов галереи категории или "". Чертежи и схемы: caption «Габаритный чертёж» / «Электрическая схема» / «Принципиальная схема».
6. Формат: фото — JPG качества 85, схемы и логотипы — PNG; длинная сторона не больше 1600 px (схемы — до 2000 px), без увеличения; уменьшение — Lanczos. "w" и "h" — фактический размер итоговой картинки. Держи общий размер файла разумным: одинаковую картинку (фото серии, схему) у разных позиций вставляй одним и тем же data URL.

СУЩЕСТВУЮЩИЕ ПОЗИЦИИ
Если модель уже есть в базе (тот же производитель и модель) — используй тот же id, что в базе (по образцам и названиям), чтобы программа обновила позицию: её цена и история цен сохранятся. Не уверен — отметь в отчёте.

ПРОВЕРКА ПЕРЕД СДАЧЕЙ
– файл — валидный JSON, "format": "kp-catalog", "version": 1;
– у каждой позиции есть id и name; id уникальны; attrs.cat — существующая категория или описанная в "types";
– числовые attrs — числа или null; значения с "values" — из списка;
– у всех позиций одного производителя одинаковый "logo";
– id блоков features уникальны внутри позиции; каждый "at": "feat:…" ссылается на существующий блок;
– каждый src — корректный data URL JPG/PNG, "w"/"h" совпадают с размером картинки;
– у каждой категории из "types" есть id, name, fields (у каждого поля key и label).

ОТЧЁТ (сообщением после файла)
• сколько позиций — по производителям и категориям; какие категории созданы и почему;
• логотип каждого производителя: откуда взят, размер;
• позиции без фото, с фото похожей модели, без логотипа, с неполными характеристиками (каких групп не хватает);
• картинки, не привязанные к модели (имя + предполагаемая модель);
• вырезанные картинки с пометкой «проверить» и причиной;
• противоречия в данных и выбранное значение;
• модели, которые, возможно, уже есть в базе, и позиции с сомнительной категорией.
