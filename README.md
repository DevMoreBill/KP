# Конструктор КП ПНЕВМОТЕХ

Программа для составления технико-коммерческих предложений (DOCX): каталог оборудования, расчёт цен,
журнал КП, контрагенты, шаблоны оформления. Собирается в **один EXE** — на компьютерах Python не нужен.
Работает на одном компьютере или как **сервер отдела** (одна база на всех, сотрудники — в браузере).

Инструкция для пользователей — [Инструкция.txt](Инструкция.txt), для администратора сервера отдела —
[server-setup/Как устроен сервер отдела.txt](server-setup/Как%20устроен%20сервер%20отдела.txt).

## Где взять EXE

GitHub → **Actions** → последний запуск «Сборка EXE для Windows» → **Artifacts**: EXE и архив «EXE + server-setup + Инструкция».

| Файл | Windows |
|---|---|
| `Конструктор КП` | 8.1 / 10 / 11, 64-бит (Python 3.12) |
| `Конструктор КП (Windows 7, 32-бит)` | 7 SP1 и новее, 32/64-бит (Python 3.8) |

Каждая сборка проверяется на Windows: запуск, база SQLite, каталог, шаблоны, типы, новый номер КП, сохранение DOCX, выход.
Релиз с файлами — тег `v*`: `git tag v1.0.0 && git push origin v1.0.0`.

```
app/kp_templates.py       шаблоны КП (папка templates): сохранение, история версий, копия, заводской вариант

app/admin.py              раздел «Настройки»: пароль администратора, удаление и корзина, модерация, журнал действий, резервные копии, статистика
app/images.py             изображения по папкам data/img/<раздел>/<категория>/<производитель> латиницей, логотипы — data/img/logos
app/equipment_types.json  встроенные типы оборудования
app/web/                  интерфейс: index.html, css/, js/ (по модулям), vendor/ — см. app/web/README.md
app/icon.ico              значок
templates/<шаблон>/       шаблон КП целиком — см. «Шаблоны КП» ниже и templates/README.txt
seed/data/                стартовый каталог (1209 позиций, без истории цен) и фото — загружаются в базу при первом запуске

kp.spec                   настройки PyInstaller
.github/workflows/        сборка и проверка EXE
```

Только стандартная библиотека Python (3.8+) и обычный JavaScript — без сборщиков. Интерфейс правится прямо в
`app/web` (обновить страницу — F5); сервер — в `app/*.py` (перезапуск `python app/kp_server.py`).

## Данные

| Где | Что |
|---|---|
| `data/img/` | изображения по папкам латиницей: `compressors/screw-compressors/dalgakiran/dalgakiran-tidy-n-3__<отпечаток>.jpg`, логотипы — `logos/<производитель>__<отпечаток>.png`; одинаковые хранятся один раз |
| `data/kp.sqlite3` | каталог, журнал КП и нумерация, контрагенты, проверки Checko, ключи API, свои типы оборудования; журнал действий (`audit`), корзина (`trash`), правки на модерации (`pending_edits`) |
| `data/backup/` | копии базы перед обновлением каталога и перед импортом в «Настройках» |
| `data/img/` | фото и логотипы (имя файла = хеш содержимого, повторы не хранятся) |
| `Коммерческие предложения/<Фамилия>/` | готовые КП `.docx` |
| `templates/` | шаблоны КП |
| `settings.json` | `mode` (`local` / `server`), `port` (17845), `dataDir` (папка данных на **локальном** диске), `docsShare` (сетевой путь к папке КП для сотрудников) |

Резервная копия — «⋯» → «Настройки» → «Резервные копии» (вся база или разделы в JSON, файл SQLite) или
`server-setup/3. Резервная копия базы.bat` (согласованная копия базы «на ходу» + фото).
Переход с прежних версий (данные в JSON-файлах `data/catalog`, `data/kp`…) — автоматически при первом запуске;
старые папки остаются нетронутыми как резервная копия. Изменения структуры базы — обратимые миграции
(`MIGRATIONS` в `app/storage.py`; откат — «Настройки» → «Пароль и доступ»). Базу нельзя класть в общую сетевую папку — для работы отделом
используется сервер отдела.

## Сервер отдела

На постоянно включённом компьютере: `server-setup/1. Установить сервер отдела.bat` (от имени администратора) —
режим сервера, порт в брандмауэре, общая папка `\\ИМЯ\КП` (чтение), автозапуск при включении, ярлык `.url` для сотрудников.
Сотрудники открывают `http://ИМЯ-КОМПЬЮТЕРА:17845/`. Общие: каталог, журнал, нумерация, контрагенты, шаблоны, типы, ключи API.
У каждого в браузере: черновик, контакты менеджера, выбранный шаблон. По сети КП скачивается («Скачать .docx»),
«Путь к файлу» копирует сетевой путь. Выключается сервер только на самом сервере.

## Возможности

- **Клиент:** реквизиты по ИНН, справочник контрагентов (объекты, контактные лица), проверка Checko (в КП не выводится).
  Загрузка клиентов списком ИНН (`app/web/js/features/clients-import.js`): вставка из Excel или файл .xlsx/.csv/.txt →
  реквизиты по одному запросу с паузой (ЕГРЮЛ ФНС или Checko/DaData) → справочник; итог — CSV для Excel.
- **Оборудование:** быстрый поиск по каталогу, плитки видов оборудования, карточка позиции с вкладками
  (основное, описание и фото, характеристики, опции, автозаполнение через Claude), фото к блокам описания,
  схемы и чертежи, дублирование позиций.
- **Категории оборудования** (`app/equipment_types.json`): ДГУ, осветительные мачты, сварочные генераторы; компрессоры —
  дизельные, винтовые, спиральные, поршневые, центробежные; подготовка воздуха — осушители адсорбционные и рефрижераторные,
  магистральные фильтры; вспомогательное оборудование — ресиверы, шкафы АВР; насосы; запасные части и ЗИП (вид, для какого
  оборудования и производителя, двигатель/узел, модели, артикул, оригинал/аналог, интервал замены); прочее. У каждой
  категории свои параметры (по группам), фильтры, быстрые опции и шаблон таблицы характеристик; поле `find` —
  из какой строки таблицы характеристик берётся значение параметра.
- **Обновление каталога** (`app/catalog_migrate.py`): при первом запуске новой версии — копия базы в `data/backup`,
  перенос позиций в новые категории, заполнение параметров из характеристик, фото от похожей модели того же
  производителя для позиций без фото; итог — в окне «Каталог обновлён». База не заменяется, меняются только записи каталога.
- **Каталог** (`features/catalog-window.js`, `features/catalog-edit.js`): дерево категорий и фильтры по параметрам типа,
  список с отметками, карточка-предпросмотр (фото, параметры, описание, характеристики, история цен). Правка позиции
  каталога в той же карточке, что и позиция КП, плюс цена в каталоге. Пакетно: добавить в КП, перенести в категорию
  (также перетаскиванием на категорию, с отменой). Новая категория — с параметрами похожей. Окно растягивается
  и разворачивается на весь экран. Импорт из Excel по шаблону, загрузка и выгрузка каталога — меню «Ещё».
- **Менеджер:** справочник менеджеров в базе (общий для отдела, таблица `managers`): выбор из списка, новый менеджер,
  правки контактов сохраняются автоматически; устройство помнит выбранного менеджера.
- **Условия:** стандартные условия плюс «Дополнительные условия и оговорки» — свободный текст под условиями в КП.
- **Титульный лист:** живое превью первой страницы КП с фото оборудования, выбор фото на титул.
- **Предпросмотр и PDF:** «Предпросмотр КП» — документ целиком в окне, без скачивания (`vendor/docx-preview`).
  PDF создаёт компьютер-сервер (`app/pdf_convert.py`): Microsoft Word, иначе LibreOffice, иначе облачный ConvertAPI
  (ключ — «⋯» → «Настройки» → «Ключи API»); галочка «Также сохранить в PDF» кладёт PDF рядом с .docx. Если ничего нет —
  печать из предпросмотра → «Сохранить как PDF».
- **Цены:** валюта КП, курсы ЦБ РФ (cbr.ru, резерв — cbr-xml-daily.ru), у каждой позиции закупка → маржа или наценка → цена.
  Скидка для заказчика по позиции (% или сумма на ед.): в КП — колонка «Скидка», «Сумма без скидки» / «Скидка», на титуле «с учётом скидки»;
  маржа и итоги — после скидки. Вывод скидки в КП включается в шаблоне (блок «Показывать скидку для заказчика»).
- **Титул:** одна или несколько моделей, получатель, объект, дата; выбор шаблона КП (настройка шаблона — в «Настройках»).
- **Типы оборудования:** `app/equipment_types.json` + свои типы (меню «⋯» → «Типы оборудования»): параметры, фильтры,
  ключевые параметры титула, быстрые опции, кнопки изображений — без правки кода.
- **Вёрстка DOCX:** страница оборудования — фото с плитками ключевых параметров, узлы карточками, характеристики — карточка на каждую группу
  в двух независимых колонках (длинные значения — текстом во всю ширину);
  без пустого последнего листа. Имя файла: `<номер>_<префикс шаблона>_<клиент>_<оборудование>_<дата>.docx`.

- **Телефон** (`css/mobile.css`, `js/ui/mobile.js`, Safari iOS и Chrome Android): шапка с кнопкой «Меню» (новое КП, журнал,
  каталог, предпросмотр, тема, «Настройки»), шаги КП строкой вверху, внизу — «‹ назад», итог и «Далее» (на последнем шаге —
  «Сохранить»). Окна — на весь экран с заметной кнопкой «✕»; каталог — поиск и «Фильтры», карточка позиции с «‹ К списку»;
  своё оборудование — «+ Вручную» в разделе «Оборудование» или «+ Позиция» в каталоге. Страница обновляется без
  пересоздания элементов (`morph()` в `core/util.js`): фото не перезагружаются, нажатия не «проваливаются», ничего не прыгает.

## Экономика сделки

Окно «Экономика сделки» (`app/web/js/features/deal.js`, расчёт — `deal-calc.js`) открывается из правой панели, раздела «Цены»,
журнала («Экономика») и меню телефона. Из КП берутся цена с НДС, ставка НДС, закупка позиций и курсы ЦБ (поля «из КП»,
любое можно изменить, «↺» — вернуть). Пересчёт — при каждом вводе. На документ КП не влияет (хранится в КП как `deal`);
цены позиций меняются только кнопкой «Перенести в цены КП».

- Формулы: R = S / (1 + v/100); прямые платежи — все платежи с налогами; себестоимость = прямые платежи − НДС к вычету +
  финансирование; прибыль = R − себестоимость; наценка = прибыль / себестоимость; маржинальность = прибыль / R;
  чистая прибыль = прибыль − налог на прибыль (25 %, можно изменить).
- Поставщики («+ Поставщик»): у каждого свои позиции, аванс, изготовление, доставка, логистика до границы (в валюте) и по России,
  таможня, «Поставщик с НДС» (вычет 22/122). «Ещё расходы»: прочая закупка (опции), страхование груза %, комиссия банка
  или платёжного агента % от платежей в валюте, брокер/СВХ/сертификация; НДС к вычету по услугам в России — авто 22/122.
- Таможня: «Сумма целиком» (с ввозным НДС к вычету; пустой — неизвестен, прибыль коридором), «Рассчитать»
  (таможенная стоимость = оборудование + логистика до границы + страхование; пошлина %; сбор — по шкале ПП РФ № 1637,
  таблица `CUSTOMS_FEES` в `deal-calc.js`; ввозной НДС = (стоимость + пошлина) × 22/10/0 % — к вычету) или «Нет».
- Монтаж и ПНР, срок ПНР, прочие расходы; «Ещё»: резерв на гарантию и бонусы/комиссии с продажи (% выручки), прочий НДС к вычету.
- Оплата заказчика этапами: % — при подписании / готовности к отгрузке / после поставки / после ПНР + дни; последний этап — остаток.
- Финансирование — простой процент (месяц = 30 дней) на недостающие деньги по графику до последней оплаты заказчика;
  стоимость денег по умолчанию — ключевая ставка ЦБ (`/api/cbr/keyrate`, cbr.ru) + 3 п.п. годовых / 12.
- Цена для КП: цель — маржинальность, наценка, прибыль или чистая прибыль → цена с НДС; «Перенести в цены КП» распределяет
  её по позициям пропорционально закупке (одинаковая наценка), опции и скидки не меняются. Показывается безубыточная цена.
- Подсказки для отдела (`/api/deal/profiles`): условия поставщика подставляются по названию, пошлина — по категории оборудования.
- График платежей с остатком денег; день строки можно изменить. «Из чего себестоимость» — структура затрат.
- «Выгрузить в Excel» — `.xlsx` с формулами: лист «Расчёт» (жёлтые ячейки — исходные данные) и «График платежей».
- Будущий модуль логистики заполняет логистику поставщика функцией `dealSetLogistics(id, {abroad:{v,cur}, ru:{v}, ship})`.
- Видят только автор КП и администратор; сервер не отдаёт расчёт чужого КП и не даёт его затереть.

## Настройки (администратор)

«⋯» → «⚙ Настройки». Вход по паролю администратора; через 15 минут бездействия вход закрывается, после 5 неверных
паролей — пауза 10 минут. Первый пароль задаётся только на самом компьютере-сервере. Забыли пароль — создайте пустой файл
`data/admin-reset.txt` и перезапустите программу: пароль сбросится, задайте новый.

Удалять КП, товары, контакты менеджеров, клиентов и свои категории можно **только здесь**: у пользователей кнопок удаления
нет, а запросы на удаление сервер отклоняет (и пишет попытку в журнал). Удалённое 30 дней лежит в «Корзине» и восстанавливается.

| Раздел | Что в нём |
|---|---|
| Статистика | КП за день / неделю / месяц и сумма, активные менеджеры, топ менеджеров и товаров, модерация, графики |
| Модерация | включение проверки правок каталога, очередь «На модерации» с разницей «было → стало», «Одобрить» / «Отклонить» с причиной; при выключении — что сделать с очередью (применить, отклонить, оставить в архиве) |
| Удаление, Корзина | выбор записей, подтверждение, восстановление |
| Журнал действий | кто, когда, что изменил (до / после), IP, браузер, результат; фильтры, поиск, страницы, откат правки |
| Резервные копии | выгрузка всей базы или разделов (JSON), файл SQLite; загрузка с проверкой и предпросмотром (ничего не удаляет, перед загрузкой — копия в `data/backup`) |
| Шаблоны и категории, Ключи API, Пароль и доступ | настройка шаблона КП, папка шаблонов, ключи, смена пароля, миграции |

Модерация: флаг `settings.productEditModeration {enabled, updatedAt, updatedBy}`. Когда она включена, правка товара
пользователем уходит в очередь (в каталоге — значок «На модерации»), а в каталог попадает после одобрения. Цены,
обновлённые при сохранении КП, проходят без модерации.

Пользователь определяется по выбранному менеджеру (заголовки `X-KP-User-Id` / `X-KP-User`) — это подпись, а не вход.
Вход администратора — cookie `kp_admin` (HttpOnly, SameSite=Strict) + заголовок `X-CSRF-Token`; пароль хранится как
хеш scrypt (резерв — PBKDF2) в базе.

## Шаблоны КП

Всё, что определяет документ, лежит в папке шаблона `templates/<шаблон>/` и правится без пересборки программы:

| Файл | Что в нём | Чем править |
|---|---|---|
| `template.json` | цвета, шрифт, стили текста (размер, цвет, начертание), все надписи с `{метками}`, порядок и включение разделов и блоков, правила раскладки, образец имени файла, тексты «О компании» | окно «Настроить шаблон» (или Блокнот) |
| `skeleton.js` | скелет документа — раскладка страниц: титул, «Наши клиенты», оборудование, таблица цен, условия, контакты, колонтитул | Блокнот (для новых блоков и компоновки) |
| `editor.json` | форма окна «Настроить шаблон»: вкладки, поля, подписи, подсказки | Блокнот |
| `base.docx` | шапка страницы, поля, размер листа, стили Word; ширина таблиц КП берётся из полей | Word |
| `clients.jpg` | страница «Наши клиенты» | окно «Настроить шаблон» |

Окно **«Настроить шаблон»** («Настройки» → «Шаблоны и категории») строится по `editor.json`: цвета с палитрой, стили с образцом,
разделы стрелками ↑ ↓, «Пробный DOCX» по текущему КП до сохранения, история версий (`_history/`) с возвратом,
копия шаблона, заводской вариант. В программе остались только общие помощники (`app/web/js/docx/kpgen.js`: суммы прописью,
даты, итоги, загрузка скелета) и подготовка изображений (`app/web/js/docx/build.js`).

## API (для справки)

`/api/ping`, `/api/catalog` (облегчённый список; `?full=1` — полный), `/api/catalog/{id}`, `/api/img`, `/img/{файл}`,
`/api/history`, `/api/kp/new`, `/api/kp/{id}/state|meta|docx|open|folder`, `/api/types`, `/api/templates`, `/tpl/{id}/{файл}`,
`/api/templates/{id}/file|history|restore|copy|reset|delete|open`,
`/api/party?inn=`, `/api/check?inn=`, `/api/integrations`, `/api/clients`, `/api/cbr`, `/api/backup`, `/api/folder`, `/api/shutdown`,
`/api/catalog/pending`, `/api/admin/status|setup|login|logout|password|stats|audit|list|delete|trash|moderation|pending|export|import|migrations`.
DELETE для пользователей закрыт (403); запись шаблонов, ключей API и удаление типов — только с входом администратора.
